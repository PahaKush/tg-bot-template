# tg-bot-template

Стартовый Telegram-бот на aiogram 3 + dishka + SQLite поверх каркаса
[tg-bot-kit](https://github.com/PahaKush/tg-bot-kit).

Демо-фича — заметки. Она прогоняет весь стек: типизированный FSM → сервис с транзакцией →
репозиторий со скоупом владения → пагинированная клавиатура → экран ошибки. Для админов
есть `/stats`, `/settings` (DEBUG-логи) и `/broadcast`.

## Быстрый старт

Python 3.12+.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env               # заполнить BOT_TOKEN и ADMIN_IDS
python cli.py initdb
python main.py
```

`python cli.py genkey` выдаёт ключ для необязательного `DB_ENCRYPTION_KEY`.

Проверка:

```bash
pytest -q && ruff check . && ruff format --check . && mypy .
```

## Слои

```
handlers/     тонкие: разобрать ввод, вызвать сервис, отрисовать. Без SQL и без правил.
services/     транзакции и доменные правила. Бросают AppError с текстом для человека.
repositories/ только SQL. Скоуп владения — здесь, в WHERE каждого запроса.
models/       коллбэки с разметкой доступа, перечисления, FSM-пейлоады.
modules/      клавиатуры и состояния FSM.
core/         DI-провайдер.
db/           база этого бота и список миграций.
```

Всё общее — база, хранилище FSM, мидлвари, экран ошибки, примитивы клавиатур — берётся
из `tgkit`. Порядок мидлварей и его причины — в `build_dispatcher()` в `main.py`.

## Главные правила

**Граница владения — в SQL, не в мидлвари.** Идентификаторы в `callback_data` приходят от
клиента и последовательны, подставить чужой — дело минуты. Поэтому `user_id` стоит рядом
с `note_id` в каждом запросе, включая чтение:

```python
row = await self.db.fetch_one("SELECT * FROM notes WHERE id = ? AND user_id = ?", (note_id, user_id))
```

Держится `tests/test_ownership.py` — копируйте его вместе со своей фичей.

**Разметка доступа на коллбэках.** Каждый `CallbackData` объявляет
`access: ClassVar[Access]`, неразмеченный коллбэк мидлварь отвергает. Тест не даёт добавить
коллбэк без разметки и считает худший случай упаковки `callback_data` против лимита
Telegram в 64 байта.

**Запись только в транзакции.** Вне `async with db.transaction()` запись падает с внятным
сообщением. Внутри транзакции чтение идёт на то же соединение, поэтому «проверил и вставил»
действительно атомарно (см. лимит заметок в `NotesManager`).

**Навигация закрывает брошенный сценарий.** «Отмена ❌» ведёт на обычный экран, и без
`AbandonedFlowMiddleware` следующий текст стал бы заголовком заметки. Хендлер, который
читает пейлоад сценария, стоит под фильтром состояния; catch-all, которому незачем рвать
ввод, помечен `@flags.keep_state`.

**Экран ошибки с навигацией.** Глобальный роутер умеет только алерт, поэтому там, где есть
осмысленное «назад», ошибка ловится контекст-менеджером:

```python
async with error_screen(edit(callback_msg), "❌ Не удалось открыть заметку.", NoteListCB()):
    note = await notes_manager.get_note(note_id, user_id)
```

`AppError` показывается как есть, остальное логируется и заменяется общим текстом.

## Тесты

```
test_ownership.py        чужая заметка недоступна на чтение и изменение
test_flow_e2e.py         сквозные сценарии через настоящий Dispatcher
test_callback_access.py  каждый коллбэк размечен; упаковка влезает в 64 байта
test_handler_layers.py   правила слоя хендлеров (стражи из tgkit.testing)
test_crypto_policy.py    шифрование работает и без ключа
test_note_input.py       заголовок и текст заметки проверяются до сохранения
```

`test_flow_e2e.py` кормит апдейтами диспетчер из `build_dispatcher()`, подменяя только
транспорт до Telegram. Так проверяется то, что живёт вокруг хендлеров: мидлвари, порядок
роутеров, разбор `callback_data`. Прямой вызов хендлера проходит мимо всего этого.

## Как добавить свою фичу

1. `models/callbacks.py` — коллбэк с `access`.
2. `models/fsm_payloads.py` — пейлоад, если ввод многошаговый.
3. `repositories/` — SQL со скоупом по владельцу.
4. `services/` — транзакция и правила, `AppError` для понятных отказов.
5. `handlers/` — экран, `error_screen` вокруг вызовов сервиса.
6. `db/migrations.py` — новая версия в конец списка.
7. `tests/` — копия `test_ownership.py` под вашу сущность.

Заметки (`handlers/notes.py`) — рабочий образец всех семи шагов.

## Обновление каркаса

tg-bot-kit закреплён тегом в `requirements.txt`: для обновления поменяйте тег и
переустановите зависимости. Править каркас вместе с ботом удобно через
`pip install -e ../tg-bot-kit`.
